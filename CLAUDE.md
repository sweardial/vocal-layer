# Voice Room

Speaker-aware layer for realtime voice AI. The product and milestones are in `SPEC.md`. Read the relevant section, not the whole thing, every time.

**Interactive session with the owner (not an unattended `claude -p` task)? Read `HANDOFF.md` first.** It explains the build system, the owner's preferences, and how to work alongside the running agents.

## Stack & commands
- Python 3.12, uv, src layout (`src/voiceroom/`), ruff.
- **Testing policy: follow `.work/POLICY.md`** (set by the human; it says whether unit tests are on).
- `make check` runs lint + smoke scripts (`scripts/smoke/`). It must be green before you finish any task.
- `make bench` runs speaker-ID benchmarks (writes `reports/`).
- Checks never touch the network or paid APIs. Anything needing a real API is a manual script under `scripts/live/`.
- Large data goes in `data/` (gitignored). Never commit audio, models, or secrets.

## How work is organized (`.work/`)
This repo is built by unattended agents driven by `agentops/cook.py`.
- `backlog.md`: ordered tasks. Only the harness changes a task's status box.
- `tasks/T-xxx/`: `plan.md`, `summary.md`, `review*.md`, `needs_human.md`, `answers.md`.
- `decisions.md`: short ADR-style log of significant choices (what, why, alternatives). Read it before changing architecture.
- `inbox.md`: notes from the human. They take priority over the plan.
- `STATUS.md`, `POLICY.md`, `state.json`: generated by the harness. Don't edit them.

## Rules
- Work only on your assigned task. If you spot other needed work, add a follow-up task at the end of `backlog.md`.
- Keep diffs focused. Prefer small modules with clear interfaces (see the architecture in SPEC.md).
- Every behavior change needs runnable proof it works, as `.work/POLICY.md` defines.
- No provider-specific code outside `src/voiceroom/adapters/`.
- Privacy: never log audio or embeddings. Encrypt stored signatures.
- Token efficiency: use the `explorer` subagent for broad code or doc searches and web lookups. Read file ranges, not whole large files. Don't paste big outputs into context. Use `tail` or `grep` on them.
- Blocked on something only a human can provide? First do everything possible with mocks. Then write `.work/tasks/T-xxx/needs_human.md` with one concise question and options, and stop.
