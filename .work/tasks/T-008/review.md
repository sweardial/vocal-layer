[MEDIUM] src/voiceroom/eval/conversations.py:80: the noise level comes from `np.mean(sig**2)` over the whole signal, inserted silent pauses included. The plan (step 3) says the SNR should be relative to speech power. → With the smoke settings (pauses 0.3-0.8 s), measuring only inside the segments gives 10.5 dB when 10 dB was asked for. With pauses of 1-3 s it gives 11.6 dB. T-011 will publish "10 dB SNR" results that are really about 0.5-1.6 dB cleaner, and the gap depends on `pause_range`, so noisy results from different pause settings can't be compared. The smoke check (smoke_conversations.py:56) measures SNR over the full signal the same way, so it can't catch this. → Compute `power` only over the segment samples (concatenate `pieces` that are utterances, or use a mask from `segments`), and make the smoke script measure SNR inside the segments.

[LOW] src/voiceroom/eval/conversations.py:90,96,101,103: `save_conversation` and `load_conversation` use `Path.with_suffix`, which replaces anything after the last dot in the stem. → If T-011 names files by SNR, e.g. `data/conv/snr10.0` and `data/conv/snr10.5`, both are written to `data/conv/snr10.wav` and `.json`. The second silently overwrites the first, and loading returns the wrong conversation. → Use `path.with_name(path.name + ".wav")` and `".json"`, or reject stems that contain a dot.

[LOW] src/voiceroom/eval/conversations.py:67: test utterances are drawn with replacement. → The SynthCorpus defaults give 4 test utterances per speaker, so a 20-turn conversation repeats the same clip many times. T-010 builds one trial per segment, so the duplicate trials are byte-identical. That inflates the trial count and narrows the apparent confidence of EER/FAR on small corpora. → Draw without replacement per speaker (shuffle, then cycle when the pool runs out) or record it, so the bench can deduplicate by `utterance_ids`.
