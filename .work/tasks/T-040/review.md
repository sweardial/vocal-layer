## Findings

[MEDIUM] src/voiceroom/policy.py:373-384: a confident match to someone who is *not* a session member is not treated as a mismatch. It falls through to `mine >= verify_threshold` and is accepted as the claimed owner. → The matcher holds a non-member signature: a revoked member (T-046 keeps running with membership changes) or any enrolled user outside the session. That person speaks on alice's track. The matcher names them confidently (e.g. 0.80), and alice's score clears the relaxed threshold (e.g. 0.58 ≥ 0.55). The turn is forwarded **labelled alice**. Reproduced with `Match('mallory', 0.8, 0.22, 'mallory', {'mallory': 0.8, 'alice': 0.58})`, which gives `ACCEPT 'alice'`. This lets an impostor get past the isolation check through the very gate this task adds. → Fix: if `match.name is not None and match.name != self.claimed`, then member → mismatch handling, non-member → unknown path. Never accept as claimed when someone else is confidently best.

[MEDIUM] scripts/smoke/smoke_room_identity.py:36,78: the smoke passes without touching either feature that defines `verified` mode. (a) I re-ran it with `verify = threshold` (no relaxation) and it still printed `room identity ok`. (b) I monkeypatched `TrackPolicy.windows_rule` to use the strict CollaborationPolicy continuity rule for verified tracks, and it also still passed. The 1–2 s owner turns are therefore not proven to need, or benefit from, the 1:1 threshold or the lenient continuity rule. A regression in either one (wrong sign on `VERIFY_THRESHOLD_RELAX`, `_Lenient` silently ignored) would stay green. → Fix: add an owner case whose whole-turn claimed score sits between `verify` and `threshold`, and assert it is accepted on a verified track and rejected/Unknown with shared/collab. Add a short owner turn with one odd window that the strict rule rejects and the lenient rule accepts. Assert the config-derived default too (see the next item).

[MEDIUM] src/voiceroom/policy.py:363-365 (bind_matcher default): the smoke always passes an explicit `verify_threshold`, so the production path never runs in any check. That path is `verify_threshold = threshold - VERIFY_THRESHOLD_RELAX * score_scale`, which picks the AS-norm threshold after binding. → If the scale or cohort handling is wrong (e.g. a cosine default left in place while the matcher returns z-scores, the bug CollaborationPolicy.bind_matcher guards against), a live verified track would accept or reject everything, and `make check` stays green. → Fix: in the smoke, build one verified TrackPolicy without `verify_threshold`, bind it to the matcher, and assert `verify_threshold == matcher.threshold - VERIFY_THRESHOLD_RELAX * matcher.score_scale` and that the owner case still passes.

[LOW] src/voiceroom/policy.py:372 / bind_matcher: if `claimed` is a member but has no signature in the matcher, `mine` is `-inf`. Every one of the owner's turns is then silently dropped (or labelled Unknown), and nothing reports it. → Example: the session lists alice, but her signature failed to load or was re-enrolled under another embedder and filtered out. Her own device is muted for the agent with no log entry. → Fix: in `bind_matcher`, raise (or log once, by name only) when `self.claimed not in matcher.names`.

[LOW] src/voiceroom/policy.py:404: the lenient continuity rule is applied to *any* enrolled label on a verified track, including one relabelled under `on_mismatch="relabel"`. Its floor also uses the relaxed `verify_threshold`. → Example: bob's turn relabelled on alice's track gets a looser floor than the 1:1 claim justifies. It also needs 2 consecutive foreign windows instead of collab's 1, and loses the long-turn `foreign-named`/`bad-run`/`deep-run` rules. A long relabelled turn that drifts into a third speaker partway through is more likely to be committed whole as bob. → Fix: use the lenient view only when `label == self.claimed`, and delegate relabelled turns to `self._collab.windows_rule`.

[LOW] src/voiceroom/policy.py:327-345: nothing validates that the factory is given a claimed identity that is a member. Instead `TrackPolicy` raises `ValueError` inside `RoomPipeline.add_source`. → Example: in T-043/T-046, a participant joins with a non-member identity and the policy factory raises inside the join handler, which can take down the room agent. Fixing that is not required for this task, but the contract is undocumented. → Fix: document in the `TrackPolicy`/factory docstring that callers must map non-member claims to `shared` or reject the join, or add a follow-up task to backlog.md.
