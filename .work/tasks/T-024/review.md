## Findings

[MEDIUM] src/voiceroom/policy.py:33-34 (interaction with src/voiceroom/matcher.py:65-71): with a cohort, Matcher scores and margins are AS-norm z-units (threshold 2.88, typical margins 1-4; my probe with the toy embedder got margin 4.12). IsolationPolicy's early-decision buffers (`early_score_buffer=0.1`, `early_margin=0.05`) are cosine-scale, and its `threshold` is passed in separately, usually as `threshold_for(name)` = 0.35. → If someone enables AS-norm (the variant D-011 recommends, and the one T-027 will ship), early accept on partial audio fires whenever matcher.name == owner, because 2.88 ≥ 0.35 + 0.1 and the lead ≥ 0.05 is always met. The "clearly confident" safety buffer disappears exactly where short-utterance FAR/FRR are worst (< 1 s 10 dB FRR is 58 %). → Fix: put the score scale in one place. Either Matcher exposes `threshold` and scale-appropriate early buffers that the policy reads, or the config holds per-scoring-mode early buffers. Also assert that policy.threshold == matcher.threshold when the pipeline is built.

[MEDIUM] src/voiceroom/config.py:25 + src/voiceroom/matcher.py:47: `ASNORM_THRESHOLDS["wespeaker-resnet34"]=2.88` only holds for the bench cohort: dev-clean enrollment windows of about 37 out-of-conversation speakers × 6 windows, top-100. AS-norm z-scores move with cohort size and composition, because top-100 of 222 rows is very different from top-100 of 5 000 rows. Yet `Matcher(cohort=any_array)` silently picks 2.88. → Once T-027 loads a real cohort file, the operating point is no longer FAR ≈ 1 %, with no warning. Higher FAR means non-owner turns reach the model. → Fix: store the threshold, with top_n and a cohort hash/size, together with the cohort file. Require a threshold whenever a cohort is passed, or calibrate it from the cohort. Also note that the "best variant wired behind config" acceptance is only half met: nothing in config or the pipeline can turn AS-norm on (T-027 covers this, but the D-011 wording "wired behind config" overstates it).

[MEDIUM] scripts/smoke/smoke_noise_robust.py:1,19-23: the docstring says "AS-norm Matcher accepts owner, rejects others". The script only checks argmax (`best == "a"`/`"b"`, and both speakers are enrolled) plus the owner score against an arbitrary `threshold=1.0`. Nothing tests an unenrolled speaker, and nothing exercises the default `asnorm_threshold_for` path. In my probe with the same setup, unenrolled synth speaker 3 was **accepted as "b"** (score 1.26 > 1.0). → The smoke stays green while AS-norm false-accepts strangers at its own operating point. The noise-aug half only checks the chunk count, so a no-op `add_noise` would also pass. → Fix: add an unenrolled speaker and assert `name is None`. Pick the threshold from the cohort (for example, the cohort's own max AS-norm score). Assert that the augmented chunks differ from the clean ones (for example, `not np.allclose(aug.chunks[n:2n], plain.chunks)`).

[MEDIUM] src/voiceroom/bench/compare.py:156-157: the cache key is `(embedder, seed, n_conv)`. It leaves out `--subset`, `--data`, AUG_SNRS, CUTS, n_speakers/n_turns/n_enroll, and any enroll/augment code change, because the cache stores fully built `Signature` objects. → Running `--subset test-clean` after a dev-clean run reuses the dev-clean embeddings, and the header still prints "LibriSpeech test-clean". Changing `add_noise` or AUG_SNRS gives a report from stale signatures with no warning. → Fix: put every input (including a version/hash of AUG_SNRS and CUTS) in the key, or drop the cache.

[MEDIUM] (gate, not caused by this diff) scripts/smoke/smoke_e2e_isolation.py:153: the timing-dependent assert `{"send_timeout","overflow"} <= codes` (stall 5 s, send_timeout 0.05 s) failed 1 of 3 runs here. → `make check` is not reliably green, and the T-024 acceptance requires a green `make check`. → Fix: belongs to T-016. Make the stall/timeout race deterministic (for example, an Event-gated provider instead of sleep timing). Either way, rerun `make check` without the background bench before accepting T-024.

[LOW] src/voiceroom/scoring.py:34-36 / matcher.py:42-44: an empty cohort of shape `(0, dim)` passes the shape check. `_stats` then returns NaN, so every score is NaN and every speaker is rejected silently (my probe printed `Match(name=None, score=nan, ...)` plus RuntimeWarnings). The cohort is also not L2-normalized, although `as_norm` assumes unit-norm rows. → A bad or empty cohort file from the future T-027 loader would turn the owner's assistant deaf with no error. → Fix: in `Matcher.__init__`, reject `len(cohort) == 0` (or `< top_n`) and l2-normalize the cohort rows.

[LOW] src/voiceroom/matcher.py:65-71: AS-norm recomputes `cohort @ centroid` plus a full sort for every enrolled speaker on every identify. It also recomputes `cohort @ x` once per signature, although that value is the same each time. These calls run on the pipeline's per-turn/early-decision path. → With a realistic cohort (thousands of rows) and several speakers, this adds avoidable latency to every early decision (T-025 is already chasing p95). → Fix: cache the enrollment-side (mean, std) per signature in `__init__`, and compute the test-side stats once per call.

[LOW] src/voiceroom/bench/compare.py:157: `pickle.loads` on `data/out/compare-cache.pkl`. → A planted or replaced cache file in the shared `data/` directory (gitignored, never reviewed) runs arbitrary code during `python -m voiceroom.bench.compare`. → Fix: store only arrays and metadata with `np.savez` and load them with `allow_pickle=False`, or remove the cache.

No HIGH findings. No audio or embeddings are logged. No provider-specific code sits outside `adapters/`. Augmentation affects enrollment only and stays off by default (`ENROLL_NOISE_SNRS=()`), so default behaviour does not change.
