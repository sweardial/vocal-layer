## Findings

[HIGH] src/voiceroom/policy.py:127-130: when `short` is set, a turn can only be rejected by `pair` (two consecutive windows that *name* another enrolled speaker) or by `deep` (`m.best != who`). With only the owner enrolled, `best` is always the owner and `name` is the owner or None. Both rules are then always false, so continuity is a no-op for every turn under 2 s. The same holds for any interloper who is not enrolled and whose closest match is the owner. → Failure scenario, reproduced: owner speaks 1.0 s and then someone else speaks 0.75-0.9 s in the same turn (turn about 1.97 s). The pipeline ACCEPTs and forwards the turn when (a) only the owner is enrolled (`run_macos_demo.sh` makes bob optional) or (b) the interloper is not enrolled. The long rule REJECTs all of these. This is non-owner speech reaching the model in isolation mode. It contradicts D-017's claim that "tails >= 0.75 s still rejected", which only holds when the interloper is enrolled and named. → Fix: keep a score-based rule on the short path that does not depend on a rival. For example, reject when two consecutive scored windows fall below `threshold - window_buffer*k` (or below the median-drop floor), whoever is `best`. Or require `scores[who]` to stay above a floor on every window except one. Add owner-only-enrollment and stranger-tail cases to `smoke_e2e_isolation.py`, and state the real leak bound in D-017.

[MEDIUM] src/voiceroom/bench/windows.py:175 (`_passes`): `pol.windows_ok(matches)` never passes `short=True`. All interjection turns are also >= 2*EDGE_S + j >= 2.5 s (line ~122). → The bench never exercises the new rule. The D-017 figures ("1-2 s owner FR 3.3 %", "windows bench for turns >= 2.5 s unchanged", the narrowband 1-2 s FR) all measure the old long rule, so the change has no offline evidence of FR gain and no measured leak cost. That is how the HIGH above got through. The acceptance criterion "bench numbers not regressed" is met only trivially. → Fix: in `_passes`, compute `short` from the turn length the same way the pipeline does. Add short interjection cases (owner 1.0-1.5 s plus a 0.5/0.75/1.0 s tail, enrolled and stranger) and report the leak for them in D-017.

[MEDIUM] src/voiceroom/bench/windows.py:216: `N_ENROLL_UTTS + 4 * a.narrowband` enrolls with 9 utterances under `--narrowband` and 5 for clean. → D-017 compares narrowband to clean ("~7 pt of owner FR, ~10 pt of 1 s leak") with different enrollment sizes and different held-out pools. The narrowband cost is understated, and someone tuning from this number will be misled. → Fix: use the same `n_enroll` for both runs, or record it in the header and the decision and rerun clean with 9.

[MEDIUM] src/voiceroom/policy.py:127 / CollaborationPolicy.windows_ok (policy.py:241): collaboration also takes the lenient path for a labelled short turn. → Failure scenario: a 1.8 s turn of alice followed by 0.5-0.9 s of bob, where only one window names bob (the mixed boundary windows name nobody). The turn is forwarded labelled "alice", so the model sees bob's words attributed to alice. Before T-035 the single-foreign guard rejected this. → Fix: in collaboration, keep the single-named-foreign-window guard on short turns. The live FR complaint was about isolation, so the change does not need to apply there. Or say in D-017 that it applies, and measure attribution on short turns.

[LOW] src/voiceroom/pipeline.py:287: `short` uses `n`, the frame count up to end of speech. That count includes the 0.2 s segmenter pre-roll and any internal pauses, not "seconds of speech" as config.py:61 and D-017 say. → A turn with 1.8 s of real speech counts as 2.0 s and takes the long rule. A 1.9 s turn with a 0.3 s internal pause also counts as long. The boundary behaves differently from the documentation and is hard to reason about in live tests. → Fix: either count voiced frames (`voiced[:n].sum()`) or reword the docs to "turn length incl. pre-roll".
