# T-016 review

`make check`: green (14 smoke scripts, 26.7 s). The smoke printed `turns=30 early=30 owner 8/8 non-owner committed=0`, latency p50=p95=385 ms, compute ~1 ms.

[HIGH] src/voiceroom/pipeline.py:81-87 (with policy.py:48-50): an early ACCEPT, decided on the first ~1 s (`MIN_DECISION_S`) of voiced audio, is applied to the whole turn. The full `ev.audio` is forwarded without checking what was said after IdentifyReady. → The owner says "hey" for 1.2 s. A non-owner then cuts in with less than `end_silence_s` (0.4 s) of gap, which happens all the time in real rooms, and talks for 10 s. The segmenter sees one turn, the early match says owner, and 11 s of mostly non-owner speech is sent to the cloud model. Without the early path, the full-turn identify would probably have rejected it. That breaks isolation's core guarantee (SPEC M1: "only owner turns are committed"). The early path also saves very little: commit still waits for TurnEnd, so it only skips one embedding call. The mirror case has the same cause: a non-owner starts, the owner continues, and the owner's request is early-REJECTed and dropped. → Fix: on an early verdict, if the turn has grown past the early audio by at least `MIN_DECISION_S`, identify the remainder (`ev.audio[len(early_audio):]`). Require it to agree, otherwise fall back to the final full-turn decision. Or start a second identify on the tail when a long turn ends. Add a smoke case for an owner→non-owner turn with no pause, and assert it is not committed.

[MEDIUM] src/voiceroom/pipeline.py:63,70: `_finish` is awaited inline in the frame loop. Identification (wespeaker p95 ~595 ms per D-009) and `provider.send_turn`, which is network I/O for the real adapter, block frame consumption. → With a live mic source (T-020), frames pile up in the source queue while a turn is decided and sent. If the queue is bounded, audio is dropped. If it is unbounded, every later turn's end-of-speech→commit time gains that backlog, and `TurnRecord.latency_s` does not show it: `endpoint_s` is in stream time and `compute_s` starts at TurnEnd processing, not frame arrival. So T-018 under-reports latency against the 700 ms target. Barge-in detection (T-022) is also delayed while `send_turn` runs. → Fix: hand TurnEnd to a single ordered worker task (asyncio.Queue) so the frame loop never awaits identify or send. Time latency from the wall-clock arrival of the end-of-speech frame.

[MEDIUM] src/voiceroom/pipeline.py:82,86,90: an exception from `matcher.identify` (embedder error) or `provider.send_turn` (dropped websocket) escapes `run()` and ends the whole session. If the early task fails before TurnEnd, its exception is never retrieved (asyncio warning). → One transient provider error mid-demo kills the pipeline, and the user's mic stops being handled. → Fix: catch per-turn errors, record the turn as dropped with an error reason (no audio in the record or log), and keep running. Retrieve or cancel the early task's exception in `finally`.

[LOW] src/voiceroom/policy.py:31-38 / pipeline.py:39-44: `IsolationPolicy` takes its own `threshold`, separate from `Matcher.threshold`, and nothing checks that they agree. The early-reject rule (`owner_score <= self.threshold - buffer`) uses the policy's copy. → For example, the CLI builds `Matcher(threshold=None)` (0.35 from config) and an `IsolationPolicy` with a different value. Owner turns are then early-rejected at scores the matcher would accept on the full turn. → Fix: default the policy threshold to None and have the Pipeline inject `matcher.threshold`, or assert they are equal in `Pipeline.__init__`.

[LOW] src/voiceroom/policy.py:52-53: an early REJECT for "confidently someone else" only needs a rival to clear the bare matcher threshold plus `early_margin` on partial audio. An early ACCEPT needs `threshold + early_score_buffer`. → With household members enrolled, a similar-voiced rival can score 0.36 against the owner's 0.30 on the first second of an owner turn. The turn is dropped even though the full turn would score the owner higher. → Fix: also require `rival >= threshold + early_score_buffer`.

[LOW] src/voiceroom/pipeline.py:40-44: nothing checks that `policy.owner` is in `matcher.names`. → If `--owner Alice` is given and the enrolled name is "alice", every turn is silently dropped (owner score = -inf), with no error. → Fix: raise in `Pipeline.__init__` if the owner is not enrolled.

[LOW] src/voiceroom/pipeline.py:85-87: turns shorter than `MIN_DECISION_S` never get an IdentifyReady and are decided on under 1 s of audio. D-009 says the M1 pipeline consumes `MIN_DECISION_S`, but this code does not use it, and the plan doesn't record a choice. → Short owner commands like "stop" or "yes" are dropped about 19 % of the time (D-009, clean <1 s FRR) with no record that the decision was low-confidence. → Fix: make the sub-minimum behaviour an explicit policy choice (decide anyway / drop / mark low-confidence in TurnRecord) and note it in decisions.md.

[LOW] src/voiceroom/pipeline.py:90: `ev.split` is ignored. → A long owner turn cut at `max_turn_s` becomes two `send_turn` calls. Each one requests a reply, so the model starts answering mid-utterance. → Fix: when `split` is set, hold the turn and send it together with the continuation, or record this as a known limitation in a follow-up task.

[LOW] scripts/smoke/smoke_e2e_isolation.py:89-101: the smoke never asserts that early decisions happen (it prints `early=30` but asserts nothing). The early-UNDECIDED → full-turn fallback path is never exercised. The toy embedder separates speakers perfectly (genuine p5 = 1.000), and the threshold is calibrated on the same held-out utterances the conversations draw from. With a sync frame source, `_aiter` never yields to the event loop, so the "early" identify thread doesn't start until TurnEnd and concurrency is untested. → If a change makes the policy always UNDECIDED, the smoke still passes and the "decides early" requirement silently regresses. → Fix: assert `early > 0`, and add one conversation with a tight buffer or ambiguous speaker that forces the UNDECIDED path and asserts it still decides correctly.
