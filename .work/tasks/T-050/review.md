## Findings

[HIGH] scripts/live/run_room_demo.sh:90-94: `voiceroom room ... | tee -a "$LOG" &` then `ROOMPID=$!`. In a background pipeline, `$!` is the PID of the **last** command, `tee`. I checked this: `sleep 30 | cat & echo $!` gives `cat`. So `stop_room` and the EXIT-trap `kill $PIDS` kill only `tee`. The `uv run voiceroom room` process keeps running. Killing `tee` does not stop it either. Python ignores SIGPIPE, so the next turn print raises BrokenPipeError, and room.py:539 catches that as "on_record callback failed". Bash also starts async jobs in a non-interactive script with SIGINT ignored, so Ctrl-C does not stop it. → Failure: the isolation-session agent from step 3 stays connected to its LiveKit room with an open OpenAI Realtime session through steps 4-12. After the script prints "Done", both agents keep running unattended. With LiveKit Cloud they keep listening. Anyone who reconnects with a still-valid token gets audio processed, sent to OpenAI and answered, while nobody is watching. This breaks the doc's "stop it before starting the collaboration room" (docs/demo-room.md:82). The "removed N revoked participant(s)" line from step 12 never appears either. → Fix: start the agent without a pipeline and capture its real PID, e.g. `$UVR voiceroom room ... > >(tee -a "$LOG") 2>>"$LOG" &`. Then send `kill -INT` so cmd_room shuts down cleanly. Python keeps SIGINT ignored if it starts ignored, so either reset it with `trap - INT` in a subshell before exec, or send TERM. Then `wait`. You can confirm with `kill -0` after stop_room.

[MEDIUM] docs/demo-room.md:116 and :140: step 8 (impostor on Alice's device) expects "a rule line in the debug log", and the results form asks "debug rule line shown: y/n". `--debug` logs only continuity rejections, after a turn was first accepted: pipeline.py:269-271 via `_continuity_ok`. A whole-turn voice mismatch on a verified track is rejected by `TrackPolicy.decide` (pipeline.py:220-222) and logs nothing. → Failure: the human correctly reports "n". The next agent reads that as T-036 rule logging being broken, or as a misconfigured run, and chases a non-bug. → Fix: in step 8 expect only `claimed=alice decision=dropped`. Point the T-036 check at the bleed step and a mid-turn speaker-change line, where `continuity reject: rule=...` actually fires. Or log mismatch rejections too, as a separate task.

[MEDIUM] scripts/live/run_room_demo.sh:127-131 (and docs/demo-room.md:116): in the impostor step Bob speaks into Alice's device while he is still joined and unmuted on his own device in a collaboration session. → Failure: Bob's own mic picks him up, and that track verifies as bob and commits `label=bob` with a model reply. Bleed suppression can also mark Alice's copy as `bleed_of=` Bob's track instead of rejecting it for voice mismatch. Either way the tester sees a committed turn, or a drop for the wrong reason, so the impostor result is wrong or doesn't test the right thing. → Fix: tell Bob to mute or leave his own device first, or have Dave, who is not in the room, do it. Ask the tester to confirm the dropped line has `source=` = Alice's track and no `bleed_of`.

[MEDIUM] scripts/live/run_room_demo.sh:49-52: when LIVEKIT_URL is unset, the warning that other devices cannot join goes to `note`, which writes only to data/room-results.txt and not to the screen. The script then goes on to give Bob and Carol tokens for `ws://127.0.0.1:7880` (line 85-87). → Failure: the operator, for example someone who forgot `.env.agent`, sets up three people. Bob's and Carol's browsers can never connect, and the 45-minute session is wasted before anyone notices. → Fix: in local mode, print the warning on screen and `yn "Continue with a Mac-only test?" || exit 1`. Better, refuse to run steps that need other devices.

[LOW] scripts/live/run_room_demo.sh:134-147 / docs/demo-room.md:117-119: step 9 puts Alice and Carol on speakers with no headphones, and nothing tells them to put headphones back on or mute Carol for the barge-in steps 10-11. → Failure: the bot reply played from Alice's speakers reaches Carol's mic and Alice's mic, depending on browser AEC. This adds spurious turns and can cause false barge-in, or hide a real one, which skews the barge-in and latency answers. → Fix: after step 9, add "headphones back on (or Carol muted) before step 10".

[LOW] scripts/live/run_room_demo.sh:158: `grep -ci "rule\|window" "$LOG"` counts every matching line in the log. That includes `uv sync`/fetch output and livekit-server logs in local mode. → Failure: it shows a non-zero "matching lines" count even when no rule line was ever logged, which nudges the tester to answer y. → Fix: `grep -c "continuity reject: rule=" "$LOG"`, which matches the describe_windows format in policy.py:154.

[LOW] scripts/live/run_room_demo.sh:63-65: the local server starts with a fixed `sleep 3` and no readiness check. Its output goes only to the log. → Failure: if port 7880 is already in use, or the server is slow, it exits silently and the first `room` run fails with a connection error. → Fix: poll `http://127.0.0.1:7880` (or `kill -0 $!`) for a few seconds and abort with a clear message.

[LOW] scripts/live/run_room_demo.sh:19: the script clears `VOICEROOM_STORE` but not `VOICEROOM_SESSIONS`, and `.env` is sourced just above. → Failure: if the user has VOICEROOM_SESSIONS set, the demo's sessions, members and pending invites go into their real sessions directory and survive cleanup, which removes only `$STORE`. → Fix: also `unset VOICEROOM_SESSIONS`, or pass `--sessions "$STORE/sessions"`.

[LOW] scripts/smoke/smoke_demo_room.py:32-42: each flag is checked against the help text of all subcommands combined, and `list`/`delete` are never checked. → Failure: a doc line like `voiceroom token --mode collaboration`, or a removed `voiceroom delete --name`, still passes, so the doc can drift from the CLI unnoticed. → Fix: extract each `voiceroom ...` command line, swap `$VARS`/`<...>` for placeholders, and run `cli.build_parser().parse_args(shlex.split(...))` in-process. That is also faster than 7 `uv run` subprocesses, and the suite is at 53 s against the 60 s budget.
